Module 2.1 ~35 min with practice

Documents the AI can read

Convert files into structured text and check what survived the transformation.

0 of 0 0%

What it is
Changing a file’s extension to .md does not convert it into Markdown.

Why learn
You avoid promising a conversion the tool can’t do. Recognizing the input structure also lets you choose specific checks for text, images, and tables.

Key concepts
Format · Structure · OCR · Extraction

What it is
Ready-made conversion tools can save work, but they need to be evaluated with documents similar to yours.

Why learn
A general benchmark doesn’t tell you whether your specific table will be preserved. Testing with a representative sample produces a decision that fits your case.

Key concepts
Sample · Compatibility · CLI · Repeatability

What it is
Markdown represents hierarchy using simple symbols.

Why learn
Explicit structure makes it easier to find information and reduces ambiguities. A number without its header can be misinterpreted even when it was extracted correctly.

Key concepts
Title · List · Table · Note

What it is
Compare totals, units, and headers.

Why learn
Structure errors are subtle and can contaminate later analyses. Checking some critical cells identifies problems that don’t show up when you just count characters or pages.

Key concepts
Header · Unit · Decimal · Formula

What it is
Keep the original file in a separate folder and record the output name, tool, date, and any warnings.

Why learn
Traceability lets you answer where a piece of information came from. It also prevents repeatedly converting identical files or continuing to use an old version without realizing it.

Key concepts
Source · Hash · Version · Manifest

What it is
Use the exercise’s fictitious data to produce a document with a title, an introduction, and a table.

Why learn
The practice teaches you to validate meaning, not just appearance. This skill will be needed when documents feed research, customer support, or automated reports.

Key concepts
Semantics · Verification · Warning · Delivery

Module 2.2 ~35 min with practice

Evidence-based research

Build a dossier that separates what the documents say from what you are concluding.

0 of 0 0%

What it is
A useful research question starts from a decision.

Why learn
A bounded question helps you recognize when the research has ended. It also makes the gaps visible—those that require new material instead of more text generation.

Key concepts
Question · Decision · Scope · Gap

What is
Organize documents by topic, date, and owner.

Why learn
The quality of the answer depends on the material consulted. A sophisticated tool does not automatically resolve contradictory, incomplete, or out-of-context documents.

Key concepts
Set · Recency · Conflict · Provenance

What is
Ask that each central conclusion be accompanied by a location: document, section, or identifiable excerpt.

Why learn
Traceability reduces the chance that fluent wording hides a claim without support. It lets someone else verify the analysis without repeating the entire search.

Key concepts
Claim · Location · Paraphrase · Inference

What is
When two documents diverge, don’t average them or silently pick whichever value is most convenient.

Why learn
Conflicts help you discover that a rule depends on conditions. Recognizing those conditions produces better answers than trying to eliminate all uncertainty from the report.

Key concepts
Divergence · Exception · Validity · Uncertainty

What is
A report is for deepening; a presentation helps guide a conversation; a questionnaire checks understanding.

Why learn
Changing the format can alter the meaning through excessive simplification. A shared baseline lets you reuse knowledge without reinventing the facts with each delivery.

Key concepts
Format · Audience · Synthesis · Consistency

What is
Use the two fictional exercise documents and write a short answer.

Why learn
Practice shows how to produce a useful answer even when the baseline doesn’t solve everything. The dossier can guide the next question instead of pretending it closed the topic.

Key concepts
Rule · Exception · Next question · Dossier

Module 2.3 ~35 min with practice

Diagrams that truly explain

Represent components and decisions without inventing connections the system doesn’t have.

0 of 0 0%

What is
A diagram needs to answer a question.

Why learn
A beautiful drawing with unclear purpose doesn’t help you decide. A clear question lets you assess whether the diagram explained the problem or just rearranged words.

Key concepts
Architecture · Sequence · Flow · State

What is
Before drawing, list participants, inputs, outputs, and where the data is stored.

Why learn
The list prevents the assistant from completing the architecture with plausible but nonexistent components. It also establishes a vocabulary that can be reviewed before changing the drawing.

Key concepts
Participant · Persistence · Hypothesis · Vocabulary

What is
A line between boxes can mean sending, reading, dependency, or order.

Why learn
Connections carry much of the meaning. Without labels and decisions, the reader may interpret causality where there is only a query relationship.

Key concepts
Connection · Label · Decision · Legend

What is
Save the diagram in a format that allows changes, in addition to the presentation image.

Why learn
An editable source reduces the cost of keeping documentation aligned with the system. It also makes it possible to review the diagram as part of a code change.

Key concepts
Editable source · Export · Version · Maintenance

What is
Ask someone to walk through a normal case and one with an error using only the drawing.

Why learn
The test measures the map’s communicative function. You check whether the reader understands the order and conditions, rather than evaluating only the aesthetics.

Key concepts
Reader · Route · Legibility · Simplification

What is
Represent a request that reaches the workshop.

Why learn
Practice teaches you to contain the drawing’s scope and represent exceptions. The result will be reused in the documentation of the final projects.

Key concepts
Input · Condition · Return · Output
